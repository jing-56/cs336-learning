| 任务 | 说明 |

**干不了的（必须上云或 WSL2+云）**

| 任务 | 原因 |
| --- | --- |
| A1 正式实验（lr 扫描、OWT、leaderboard） | 4 GB 装不下 handout 的配置；B200 上 20–30 分钟/次，本地要跑一整天 |
| A2 的 Triton / nsys / 2 卡 DDP / FSDP | Windows 没有官方 Triton；2 卡需要两张卡 |
| A4 的最终训练评测 | 官方配置 8×B200 × 2 小时 |
| A5 的 GRPO | 1B 模型 + vLLM，需要 2 张 24 GB 以上的卡 |

**显存换算参考**（bf16，训练）：参数 2 字节 + 梯度 2 字节 + AdamW 动量与方差 8 字节 ≈ **12 字节/参数**，再加激活（与 batch×ctx×层数成正比）。

- 10M 参数 → 约 0.12 GB 状态，4 GB 卡能带得动 ctx 256 / batch 32
- 100M 参数 → 约 1.2 GB 状态，4 GB 卡只能 batch 4~8、ctx 128
- 1B 参数 → 约 12 GB 状态，4 GB 卡直接放弃

## 4. 上云的正确姿势

1. **本地把逻辑调对再上云。** 所有作业都支持 CPU 跑通（`device='cpu'` 或极小配置）。云上调试的每一分钟都在烧钱。
2. **先跑 20 步。** 所有训练脚本先 `--max-steps 20`，确认 loss 在降、显存没爆、checkpoint 能存，再放开跑。
3. **用抢占式/按秒计费**，并且**写好断点续训**（A1 的 checkpoint 那题正好练这个）。
4. **实验前写假设，实验后立刻存图。** 云端实例关掉就没了，wandb 是唯一的保险。
5. **把"跑什么"写成脚本**，别在 notebook 里手动改参数——A1 的 `experiment_log` 要的就是这个。

## 5. A3 的替代方案（自学者必读）

A3 的训练 API 需要 **8 位 Stanford 学号当 key + 校园网/VPN**，非在校生拿不到。但 A3 的核心是"**用有限预算拟合缩放定律**"，这件事你自己就能做：

**改版方案（推荐）**

1. 用 A1 的代码，在 TinyStories 或 OWT 子集上跑 **10–14 个小模型**：
   - 固定 token 预算 D ≈ 1–3 B，扫 N ∈ {2M, 4M, 8M, 16M, 32M, 64M}（6 个点）
   - 再固定 N ≈ 8M，扫 D ∈ {0.1, 0.3, 1, 3 B}（4 个点）
2. 用 `L = E + A/N^α + B/D^β` 做最小二乘拟合（`scipy.optimize.curve_fit`，注意 log 空间拟合更稳）
3. 画 IsoFLOP 曲线：每个 C 取最低点，得到 N_opt(C) 和 D_opt(C)，拟合幂律指数
4. 外推到 C = 10²³、10²⁴，和 Chinchilla（N_opt ∝ C^0.5, D_opt ∝ C^0.5）对比，讨论偏差来源

**成本**：单卡 4090 约 8–15 小时 ≈ $5–10；本地 3050 也能跑，只是要 2–3 天。

**写 writeup 时明确声明**：数据规模、tokenizer、架构与官方 API 不同，"绝对数值不可比，但拟合方法与结论可比"。这样这份作业依然成立，甚至更有说服力——因为你真的跑过。
