# 2026-11-07 A1｜OpenWebText 全量分词、编码和本地训练

用完整 OpenWebText 训练语料训练了 **32,000 项 BPE 词表**，并用同一词表编码完整的训练集和官方验证集。在 RTX 3050 Laptop 上，4 层学习模型训练 **20,000 步**，固定验证批次的平均交叉熵从 **10.3782** 降到 **4.9594**。

| 阶段 | 实测结果 |
| --- | --- |
| 全量预分词 | 118.16 亿字符、2,399,397 个文档结束标记、6,601,892 种不同片段，耗时 47 分 5 秒 |
| 32K BPE | 31,743 轮合并，从读取频率表到保存词表耗时 12 分 52 秒，峰值工作集 5.34 GiB |
| 训练集编码 | 2,727,120,452 个 token，uint16 数组约 5.45 GB，耗时 38 分 59 秒 |
| 验证集编码 | 66,401,098 个 token，59,059 个结束标记，耗时约 60 秒 |
| 语言模型训练 | 9,045,120 个参数，20,000 步、40,960,000 个目标位置，耗时 32 分 49 秒 |

## 从频率表到 32K 词表

预分词计数与 BPE 合并各自保存结果。第一轮全量合并因电量暂停。第二轮在第 476 轮触发内存保护，当时系统可用内存低于 1.5 GiB。新版用位图保存密集的片段编号，只更新实际发生变化的相邻对，并复用每轮生成的 token 字节串。相同全量频率表下，进入合并阶段的进程工作集从约 3.50 GiB 降至 2.52 GiB。

50 MiB 样本中，新版的 32,000 项词表与 31,743 条合并规则均与原结果逐项一致。全量词表在留出的 10 篇网页文档上产生 7,582 个 token，全部可以逐字还原。

## 编码和训练

编码使用训练所得的词表、相同的正则预分词规则和 EOS ID 256。加速编码器在 112 个训练、验证及边界样例上与原 Python 实现的 token ID 逐项一致。全量编码逐块检查字节还原和 EOS 计数，写成支持按批读取的 `.npy`。断点测试模拟了意外中断和文件末尾多写的字节，续跑结果与一次性编码一致。

训练沿用 4 层、模型宽度 128、4 个头、前馈宽度 384、上下文 256、batch 8 的配置。训练批次在完整训练数组上随机取样，每步预测 2,048 个位置。Windows 上的 NumPy 随机下标默认是 32 位整数，大数组的取样入口显式使用 64 位下标，并在 GPU 上验证了超过 2³¹ 的位置。

每 100 步用同一组固定验证批次评估，每次覆盖 20,480 个目标位置。4.9594 是这组批次的平均 loss。20,000 步累计预测的 4,096 万个位置来自随机取样，训练没有遍历一整轮语料。这次使用本地学习配置，课程原始尺寸实验仍待补。

## 生成样例

从第 20,000 步存档接续 `The city council announced on Tuesday that`，固定 seed=42、temperature=0.8、top-p=0.9，生成 256 个新 token。输出模仿了报道的段落和引语格式，人物、事件及其关系经常跳转。训练预算和模型宽度限制了模型能学到的关联，采样参数也会影响局部措辞。这些因素没有在本次单个样例中分开比较。
