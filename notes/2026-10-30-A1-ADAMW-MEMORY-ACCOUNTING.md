# 2026-10-30：AdamW 激活内存与 batch size 的简化核算

延续讲义 `adamw_accounting`（印刷页 32–33）的（a）和（b），将“固定状态 + batch×单序列激活”展开。本记录给出一套明确的简化记账方法，不是测得的训练峰值，也不能保证实际 batch 能装入。

## 采用的激活记账口径

FP32 每个元素 4 字节。按题目列出的主要算子各保留一份输出，交叉熵额外计一份 BT×V 的中间张量；不分析 autograd 实际保存、共享和释放张量的时机。

| 每层激活部分 | 计入元素数 |
| --- | --- |
| 两个 RMSNorm 输出 | 2BTd |
| Q、K、V 投影输出 | 3BTd |
| QK 分数与 softmax 权重 | 2BHT² |
| AV 输出与注意力输出投影 | 2BTd |
| SwiGLU：W1、W3、SiLU、逐元素乘积、W2 输出 | 4BTf+BTd |
| 每层合计 | BT(8d+4f+2HT) |

模型末尾再计最终 RMSNorm 的 BTd、logits 的 BTV、交叉熵中间张量的 BTV。因此：

```text
A_bytes(B) = 4BT[L(8d+4f+2HT)+d+2V]
```

按讲义在 AdamW 核算题中指定 f=8d/3 时：

```text
A_bytes(B) = 4BT[L((56/3)d+2HT)+d+2V]
P = 2Vd + L(12d²+2d) + d

参数存储 = 4P
梯度存储 = 4P
优化器 m/v 状态 = 8P
上述记账总和 = 16P + A_bytes(B)
```

P 的公式沿用无偏置、输入输出权重不共享、标准多头注意力、RMSNorm、SwiGLU 的作业架构。

这套统计把列出的输出都累加，不声称它们在真实实现中都同时独立驻留。未额外统计输入 Embedding 输出、残差输出、归一化内部统计量、softmax/交叉熵的全部内部临时量、反向临时量、优化器临时量、固定 RoPE 表、数据、工作区、分配器等。有的引用也会共用存储，简单相加可能重复计数。因此实际峰值既不能直接取此数，也不能把它作为经过证明的上界或下界。

## 16.37 GB 怎样得到

先沿用此前具体 XL 配置：B=1、T=1024、L=48、d=1600、H=25、V=50257、f=4288。以下已经合计全部 48 层：

| 部分 | 存储量（十进制 GB） |
| --- | ---: |
| Block 内 RMSNorm 输出 | 0.629146 |
| QKV 输出 | 0.943718 |
| 注意力分数与 softmax 权重 | **10.066330** |
| AV 与注意力输出投影 | 0.629146 |
| SwiGLU 输出 | 3.686793 |
| 最终 RMSNorm | 0.006554 |
| logits 与一份 CE 中间张量 | 0.411705 |
| **合计** | **16.373391** |

一个头的打分表是 1024×1024。25 个头的一张完整分数张量有 26,214,400 个元素，占 104,857,600 字节，约 0.104858 GB（100 MiB）；权重表再算一份。48 层合计约 10.06633 GB，仅这部分就超过单序列激活估算的六成。

这里的“每条序列”不是训练语料文件的大小，而是一个 1024-token 输入通过所有层时，按上述规则累加的中间张量。

## 80 GB 的估算结果与取整差别

此前 transformer_accounting 的 XL 参数指定 f=4288；AdamW 题则要求假设 f=8d/3。后者是连续维度的代数近似，实际张量宽度仍需取整数。这两个口径的数字略有不同，不能混用，但本次都得到整数 batch=3。

| 口径 | 固定状态 GB | 每序列激活 GB | B=3 合计 GB | B=4 合计 GB |
| --- | ---: | ---: | ---: | ---: |
| 具体配置 f=4288 | 26.247245 | 16.373391 | 75.367419 | 91.740810 |
| AdamW 题假设 f=8d/3 | 26.168602 | 16.356614 | 75.238444 | 91.595058 |

以题目连续近似口径、80GB=80×10⁹ 字节为例：

```text
M_GB(B) ≈ 26.1686016 + 16.356614144 × B
B_max = floor((80-26.1686016)/16.356614144) = 3
```

这是这套简化口径中的最大整数，不是实际部署时可靠的最大 batch。混合精度、FlashAttention、激活重算、参数或优化器分片会改变估算条件；本次没有使用这些方法，也没有测量 GPU 内存。
