# 2026-10-29：当前小模型的前向 FLOPs

## 统计口径

FLOPs 指浮点运算量。使用常见矩阵乘法口径：形状 (m,n) 与 (n,p) 相乘约为 2mnp FLOPs，一次乘法加累加计为两次浮点运算，忽略精确加法次数的低阶差别。GFLOPs 是十亿次浮点运算；FLOP/s 才是每秒运算速度。

这里只核算一次完整序列前向中的主要稠密矩阵乘法，不是完整前向所有算子、更不是一个训练步的全部开销。未包含 Embedding 查表、归一化、softmax、RoPE、SiLU、门控乘法、残差相加、遮罩、loss、反向传播、优化器更新与数据移动。这些被省略的操作不代表实际不消耗时间或内存。

配置：B=4、T=64、d=64、f=128、V=10,000、L=2、注意力头数 H=4，每头维度 d_h=16。参数量仍为 1,362,240。

## 逐项计算

把 B×T 个 token 的特征视作 (BT,d)，一个 d→d 的投影约为 2BTd² FLOPs。权重矩阵会在不同 token 上重复使用，因此输入变长会增加运算，不需要增加权重数量。

每层四个注意力投影（Q、K、V、输出）合计 8BTd²。

每个头的 QK 打分是 (T,d_h)@(d_h,T)，共 B×H 份，成本为 2BHT²d_h=2BT²d。AV 加权求和是 (T,T)@(T,d_h)，同样为 2BT²d。两项合计 4BT²d。

SwiGLU 三张矩阵，各有约 2BTdf 的投影成本，合计 6BTdf。

输出投影将 (BT,d) 映射到 (BT,V)，成本为 2BTdV。Embedding 则是按 token ID 查行，没有对应的稠密矩阵乘法。

| 项目（层内项目已合计两层） | FLOPs |
| --- | ---: |
| Q、K、V 投影 | 12,582,912 |
| 注意力输出投影 | 4,194,304 |
| QK 打分 | 4,194,304 |
| AV 加权求和 | 4,194,304 |
| SwiGLU 三次投影 | 25,165,824 |
| 输出词表投影 | 327,680,000 |
| **合计** | **378,011,648，约 0.378 GFLOPs** |

当前结构的主要前向矩阵乘法公式为：

```text
F = L(8BTd² + 4BT²d + 6BTdf) + 2BTdV
```

输出词表投影约占 86.69%。这与当前模型窄、层数少、词表相对较大的配置有关，不能推广到所有语言模型或长上下文设置。

## batch 和序列长度的影响

| 配置 | 主要矩阵乘法 FLOPs | 相对基线 | QK+AV 相对基线 |
| --- | ---: | ---: | ---: |
| B=4，T=64 | 378,011,648 | 1 倍 | 1 倍 |
| B=8，T=64 | 756,023,296 | 2 倍 | 2 倍 |
| B=4，T=128 | 772,800,512 | 约 2.0444 倍 | 4 倍 |

B 加倍会让本统计范围内每一项都加倍。T 加倍时，投影处理的 token 数加倍，所以 QKV、注意力输出投影、FFN 和输出词表投影都加倍；QK 与 AV 中出现 T²，因而变为四倍。

直观看，每个头的打分表从 64×64=4096 个位置对变成 128×128=16384 个位置对，变成四倍；每个位置对的点积维度仍为 16。AV 的矩阵乘法也有相同的 T² 变化。

注意“QK+AV 变成四倍”与“整个注意力模块变成四倍”不同：整个注意力模块还包括只加倍的四个投影。更不能把整模型都写成四倍。

T=128 这一行是把上下文扩展到 128 后的假设核算，没有直接运行原上下文上限为 64 的模型。扩展本实现的上下文需要配置新的 RoPE 表，但不会增加可学习参数。

当前 `attention.py` 先计算完整 QK 分数矩阵，再遮罩未来位置；之后 AV 仍执行稠密矩阵乘法。因此本次按完整方阵核算，没有因为语义上只允许看过去就把运算量减半。使用专门优化的因果注意力实现时需重新明确统计口径。

FLOPs 比值不是实测耗时比值。不同输入规模会影响计算效率，且本统计没有覆盖所有算子和内存开销。
